# 과제 11 - 삽입 정렬과 쉘 정렬의 성능 비교

`gcc -O2 -o shell_compare shell_compare.c` 로 컴파일한다. 실행하면 난수 시드를 묻고, Enter를 누르면 기본 시드(12345)로 아래 결과가 재현된다.

비교 횟수는 **데이터 값끼리 맞대어 본 횟수**만 센다. 반복문 인덱스 검사, 데이터 생성, 배열 복사는 세지 않는다. 각 크기마다 세 방법이 같은 원본의 복사본을 사용했고, 모든 경우 오름차순 정렬이 확인되었다.

## 측정 결과

| n | 삽입 정렬 | 쉘(기본) | 쉘(Knuth) | 삽입/기본 | 삽입/Knuth |
|---|---|---|---|---|---|
| 1,000 | 245,972 | 15,008 | 13,700 | 16.4배 | 18.0배 |
| 2,000 | 1,006,726 | 35,920 | 34,911 | 28.0배 | 28.8배 |
| 4,000 | 3,961,853 | 82,633 | 76,457 | 47.9배 | 51.8배 |
| 8,000 | 16,172,030 | 212,264 | 176,939 | 76.2배 | 91.4배 |
| 16,000 | 63,830,262 | 500,158 | 405,867 | 127.6배 | 157.3배 |
| 20,000 | 100,211,933 | 623,182 | 525,257 | 160.8배 | 190.8배 |

**데이터가 2배가 될 때 비교 횟수의 증가 배율**

| | 삽입 정렬 | 쉘(기본) | 쉘(Knuth) |
|---|---|---|---|
| 1,000 → 2,000 | 4.09배 | 2.39배 | 2.55배 |
| 2,000 → 4,000 | 3.94배 | 2.30배 | 2.19배 |
| 4,000 → 8,000 | 4.08배 | 2.57배 | 2.31배 |
| 8,000 → 16,000 | 3.95배 | 2.36배 | 2.29배 |

## 분석

**크기가 커질수록 격차가 벌어진다.** n이 2배가 될 때 삽입 정렬은 **약 4배**, 쉘 정렬은 **약 2.3배**씩 늘었다. 삽입 정렬이 4배인 것은 비교 횟수가 n²에 비례한다는 뜻이다. 실제로 n=20,000에서 100,211,933회는 n²/4 = 100,000,000과 거의 같다. 무작위 데이터에서 한 원소가 평균적으로 정렬 구간의 절반을 밀고 가기 때문이다. 쉘 정렬의 2.3배는 n²(4배)보다 n log n(약 2.2배)에 훨씬 가깝고, 이론적으로 알려진 O(n^1.25~1.5)와 맞아떨어진다. 그 결과 n=1,000에서 16배였던 차이가 n=20,000에서는 **160~190배**까지 벌어졌다.

**왜 쉘 정렬이 빠른가.** 삽입 정렬의 약점은 **원소가 한 번에 한 칸씩만 움직인다**는 것이다. 맨 뒤에 있는 작은 값이 맨 앞으로 가려면 비교와 이동을 n번 가까이 해야 한다. 쉘 정렬은 처음에 간격을 크게 잡아 **멀리 떨어진 원소끼리 먼저 비교**하므로, 한 번의 이동으로 수천 칸을 건너뛸 수 있다. 큰 값이 한 번에 뒤로, 작은 값이 한 번에 앞으로 가서 배열이 빠르게 "거의 정렬된" 상태가 된다. 마지막 간격 1의 단계는 삽입 정렬과 똑같은 코드지만, 이때는 이미 정렬에 가까워서 대부분 첫 비교에서 멈춘다. 즉 쉘 정렬은 **삽입 정렬이 가장 잘하는 상황(거의 정렬된 입력)을 스스로 만들어 주고 나서** 삽입 정렬을 쓰는 방식이다.

**기본 간격과 Knuth 수열의 차이.** Knuth 수열이 모든 크기에서 더 적었고, n이 커질수록 차이가 커져 n=16,000에서 **1.23배**(500,158 대 405,867)까지 벌어졌다. 작은 n에서는 1.03~1.10배로 차이가 미미했다.

**간격 수열이 성능을 좌우하는 이유**는 **간격끼리의 약수 관계** 때문이다. 기본 간격 n/2, n/4, n/8, ...은 모두 2의 배수로만 줄어든다. n=1,000이면 500, 250, 125, 62, 31, ... 처럼 초반 간격이 전부 짝수라서, **짝수 번째 자리의 원소와 홀수 번째 자리의 원소가 서로 비교되지 않는다.** 서로 다른 그룹끼리 섞이지 못한 채 같은 일을 반복하다가, 간격이 홀수가 되고 나서야 비로소 섞이기 시작한다. 앞 단계의 작업이 헛도는 셈이다.

Knuth 수열 1, 4, 13, 40, 121, 364, 1093은 이웃한 간격끼리 공약수가 1이다(예: 364와 121은 서로소). 그래서 매 단계가 **직전 단계와 다른 원소 조합을 비교**하게 되고, 단계마다 실제로 정렬 상태가 개선된다. 중복되는 비교가 적어 같은 일을 더 적은 비교로 끝내는 것이다. 또한 간격이 약 3배씩 줄어 단계 수가 기본 방식(약 log₂n = 14단계)보다 적은 것(약 log₃n = 9단계)도 유리하게 작용한다.

**정리.** 쉘 정렬은 삽입 정렬의 "한 칸씩만 이동" 제약을 간격으로 깨뜨려 성능을 수십~수백 배 끌어올린다. 그리고 그 성능은 어떤 간격을 쓰느냐에 따라 또 한 번 달라지며, **이웃한 간격이 서로소인 수열일수록 각 단계가 헛돌지 않아 유리하다**는 것을 Knuth 수열의 결과가 보여준다.
